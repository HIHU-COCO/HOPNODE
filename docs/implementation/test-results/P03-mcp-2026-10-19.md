## Linux race 首次失败与修复复测

同日集成方在 Linux 首次追加 `go test -race ./...` 检查，结果 **FAIL（DATA RACE）**。此前 Windows 普通 test/vet PASS 不足以发现该问题。原测试 `lockedBuffer` 匿名嵌入 `bytes.Buffer`，意外向外暴露其 `ReadFrom`；`os/exec` 的 `io.Copy` 走 `ReadFrom` 快路径，绕过包装器 `Write` 的锁，与测试中的 `text()` 并发读取发生竞争。

修复将匿名嵌入改为未导出命名字段 `buffer bytes.Buffer`。仅由加锁的 `Write` 与 `text` 访问底层 buffer，不提供 `ReadFrom`，使 `io.Copy` 经过加锁的 `Write`。不改变协议服务或生产接口。

修复后在 POC 工作树重新执行：

| 环境 / 实际命令 | 结果 |
| --- | --- |
| Windows Go 1.27.2：`gofmt -w main_test.go` | PASS |
| Windows Go 1.27.2：`go test -count=1 -v ./...` | PASS，exit 0，SDK 及四个旧协议子进程均通过 |
| Windows Go 1.27.2：`go vet ./...` | PASS，exit 0，无输出 |
| WSL Ubuntu-22.04，Go 1.27.2 linux/amd64：`go test -race -count=1 -v ./...` | PASS，exit 0，`ok hopnode.local/pocs/mcp 6.197s`，未报告 DATA RACE |

Linux 复测使用根目录 `.tools/go-linux/go/bin/go`，内核为 `Linux 6.18.33.2-microsoft-standard-WSL2`。此结果只补充 WSL 的真实 Linux 协议/并发测试证据，不能替代 Ubuntu Desktop GUI、Ubuntu Server 真机或 Codex 模型调用验收。首次 race FAIL 已修复，不保留为未解决阻塞；P03 的 Codex 认证/实调用阻塞仍存在。
