## 环境与执行方式

- Windows 11 x64 本机 Python 3.14.7 隔离 venv；WebSSH 1.6.3，上游源码 commit `aaac2afe2a0d0c2fb8a8fd0813462d354682888a`。按该源码 requirements 使用 Paramiko 3.5.1 / Tornado 6.5.1。
- Playwright 1.64.1 控制独立 headless Edge；临时浏览器 context 不沿用用户浏览器数据。请求路由只允许本机回环页面；未开启 tracing/HAR，也未收集浏览器 console 内容。
- 远端为用户已经授权的 Ubuntu Desktop 22.04 x86_64，使用既有 SSH。目标地址、账号、口令、会话 ID 和主机公钥均不收入 Git。
- 上游源码、venv、浏览器依赖、截图、原始输出和本地脱敏结果仅保留在忽略的 `.tools/`；未修改根依赖、用户 SSH/Tailscale 配置或远端服务。

实际启动参数如下；`<PINNED_KNOWN_HOSTS>` 为先前已核验的独立 Ed25519 文件，两项都显式指定，未使用系统默认文件。

```text
python -m webssh.main
  --address=127.0.0.1 --port=18888
  --policy=reject
  --hostfile=<PINNED_KNOWN_HOSTS> --syshostfile=<PINNED_KNOWN_HOSTS>
  --xheaders=False --origin=same --xsrf=True
  --debug=False --logging=error --encoding=utf-8
  --timeout=10 --maxconn=1
```

使用本机回环 HTTP 页面输入密码；密码未放入 URL、启动参数或持久配置。private key/passphrase/TOTP 留空。没有部署公网或 LAN WebSSH 服务。上游 debug 日志会涉及输入和终端流，因此本轮禁用 debug；这些参数不构成公网部署方案。

终端连接后，仅在该会话执行 `unset HISTFILE; set +o history`、设置合成 PS1、清屏和只读 Python/系统信息查询。查询读取 `/etc/os-release`，核验当前用户是否匹配授权账号、`platform.machine()`、`os.isatty(0)` 与 `os.get_terminal_size(0)`，并输出合成中文字符串；不读取用户业务文件，不执行 sudo、安装、服务或网络配置修改。

## 自动化故障与退出证据边界

首轮 SSH/PTY/中文/resize 已成功，但截图脚本等待 `.xterm-rows` 文本超时，Node 工具重置内核；当时没有完成正常 exit 或视觉 QA。后续核查该轮确切服务 PID、端口监听和自建 Playwright 浏览器均已消失。该结果只证明本机资源回收，不证明远端后台任务结束。

第二轮改为直接截图并人工查看，完成上述视觉 QA；发送 exit 后，Playwright close 观察器在 8 秒内未置位，随后按确切进程清理。第三轮在关闭 context/browser 或终止服务之前，补查远端 exit 输出、终端节点消失及上游 send API 清除，前端终端会话关闭行为得到间接证据；该观察器在 10 秒内仍未置位，作为独立的可观测性缺口保留。没有证明 SSH exit-status、WebSSH 服务正常退出或远端进程树终止，也没有将工具超时、观察器缺失或本地进程退出当成远端任务终止/异常断线验收。

本地证据：`.tools/webssh-proof/qa-inventory.json`、`sanitized-results.json`、`login-empty.png`、`terminal-sanitized.png`。截图已目视检查，原始 stderr/终端数据不提交；口令已从测试变量清除，浏览器 context 已关闭。
