# P05 条件施工顺序（已授权）

日期：2026-10-19（Asia/Shanghai）。状态：**ACCEPTED，已授权并生效**。决策见 [ADR-0001](../../decisions/ADR-0001-v1-stack.md)；G0/G1/P05 为 CONDITIONAL，K01 为 READY，未完成原有实测或冻结契约。

授权依据：用户在获知调整原因及返工代价后指示“那你重新调整，调整完之后告诉我。” 本次执行只调整施工与复测顺序；全平台、F01–F18、A01–A27 保留，测试授权范围不扩大，不授权发布。

## 提案缘由

Windows/Ubuntu 22.04 GUI 与独立 Core IPC、工程包安装/卸载、真实 Codex MCP 调用、SSH/PTY/SFTP 已有局部实证。Windows Server 2022 临时 CI 也已实际完成 SCM 两轮启停、服务身份管道负例及删除清理，见 `tests/pocs/service-lifecycle/SCM-CI.md`。独立 Headscale/Tailscale 的单机机制验证见 `tests/pocs/network-isolated/RESULTS.md`；单机结果不能代替不同网络或强制 DERP 回退。

尚缺 Windows 10/11 系统服务及受控 SSH、Ubuntu 24.04/全新 Server、不同网络/公网 DERP、完整服务调用者身份、注销重启和升级恢复等证据。当前工程是诊断预览，业务功能未交付，正式验收仍为 0/27。

原 `AGENTS.md` V1.0 §3 要求“T → P → K 阶段通过且证据齐全后，才并行 N、R、M、U、S、C 六条开发线”；`Plan.md` G1 允许“明确授权的替代路线”。本次在明确授权后同步更新 Plan V1.3、AGENTS V1.1 与台账；已有缺口继续登记，不能据此标为通过。

## 生效的施工顺序

以已实测的 React/TypeScript/Ant Design/Tauri 2、Go、SSH/SFTP、Tailscale/Headscale 架构进入**有条件的 G0/G1/P05 施工出口**，将缺环境的实机验证保留为独立阻塞项，允许继续 K01–K04 和随后满足依赖的业务开发。原 POC 完成判据、各模块真机验收和发布门槛保留。

1. 先完成 K01：补齐 Directory 注册/心跳/停用的候选协议、完整 IPC 方法与事件、26 个 MCP 工具结果、版本协商、身份与取消/未知结果语义，以及 Go/TypeScript 共享或生成类型。已有离线片段仍是草案，不能直接宣布 K01 完成。
2. 每个未决安全策略须先写清决策和拒绝行为，再由集成负责人收敛契约。网络不可用、身份不匹配、能力未验证或结果未知时返回明确错误/能力状态；不伪造成功，不自动重放可能产生副作用的操作。
3. K01 机器校验和审查通过、合入集成基线后，再严格串行推进 K02→K03→K04。只有 G2 证据齐全，才按目录责任及模块依赖并行六条业务线，继续共享同一 Go Controller/IPC 实现。P01–P04 尚缺的实测不再一概阻止对应实现；未满足某任务原有完成判据时，该任务不得设 DONE。
4. Windows 10/11、Ubuntu Desktop/Server 两版本、不同网络/DERP、服务身份、恢复/升级等未运行项保留 `NOT_RUN/BLOCKED`，持续补测。现有用户 SSH/Tailscale/Codex 配置不得被覆盖。
5. 候选包依 Plan 在 G5 通过后执行 L01–L05 构建，再以候选包完成依赖它的真机验收及 L06；L07 正式发布仍需全部 F/A 追踪和 27/27 PASS。任何测试替代品、CI Server OS、WSL 或单机组网均不得冒充对应真机验收。

## 执行与复测规则

- 第一项可启动任务为 K01；K02–K04 及六条业务线保持 TODO，不能因授权直接设为完成或提前启动。
- T03/P01–P04 按事实保持 BLOCKED/IN_PROGRESS，G0/G1/P05 的 CONDITIONAL 只表示开发出口获准；原有测试通过之前不改为完整 DONE/PASS。K04 的 A25 待测数值继续列明冻结条件，不伪造性能基线。
- 缺失环境和风险的责任、验证与解除条件见 ADR-0001、risks.md、test-environment.md。有环境时复测原 POC；发现失败推翻共享假设时暂停受影响契约/模块，先处理 ADR 和迁移，再复测。
- G3–G6 的原有真实闭环、全平台包、升级/恢复及 27 项验收门槛保留；本次授权不允许发布工程预览为正式产品。
- 当前授权由本文件与 ADR 持续记录；同一路线后续实施不重复请求施工顺序确认。新增设备、破坏性操作或超出原授权的系统变更仍按实际权限处理。
